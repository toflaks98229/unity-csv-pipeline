## 2. 이번에 새로 찾은 것

### D1. 중복 식별자를 경고 없이 삼킵니다 — **가장 심각**

`Id` 가 같은 행이 둘이면 **뒤 행이 앞 행을 덮고, 아무도 알려 주지 않습니다.**

근거 — `코드`:

- `CsvRowImporter.AssetPathFor` (`Editor/Importing/CsvRowImporter.cs:51`) 와
  `CsvSchemaImporter` (`Editor/Schema/CsvSchemaImporter.cs:71`) 가 `{folder}/{id}.asset` 로 곧장 갑니다.
  같은 `id` 면 **같은 경로**입니다.
- 앞 행은 `isNew = true` 로 생성, 뒤 행은 `isNew = false` 로 갱신이 됩니다 (`CsvRowImporter.cs:83`).
  리포트는 `생성 1 / 갱신 1` — **정상적인 임포트와 구분되지 않습니다.**
- 집계는 `HashSet<string> validNames` (`CsvImportDefinition.cs:160`) 라 겹친 식별자가 **조용히 접힙니다.**
  개수로도 드러나지 않습니다.
- 미리보기도 같은 경로에 `생성` 한 줄, `갱신` 한 줄을 나란히 올릴 뿐 경고가 없습니다
  (`CsvRowImporter.cs:114`~`:119`).

이 결함의 성질은 이 패키지가 이미 막고 있는 것들과 정확히 같은 종류입니다 — **사람이 표에서 실수했고,
도구가 그 실수를 삼켰고, 알아차릴 방법이 없습니다.** 표가 커질수록(행 복사·붙여넣기) 확률이 올라갑니다.

> 흥미로운 점: `SheetDiff.IndexByFirstField` 는 이미 **겹친 식별자를 알아채고 안내합니다**(v0.8.0에서
> 순수 함수로 떼어 내며 찾은 것). 시트 쪽에서 잡는 것을 임포터 쪽에서 못 잡고 있습니다.

**고치는 법**: `BakeEach` 에 이미 있는 `validNames` HashSet 의 `Add` 반환값을 보면 끝입니다.
겹치면 `report.Warn(줄번호, "식별자 'X'가 N행에서 이미 쓰였습니다. 뒤 행이 앞 행을 덮습니다.")`.
계획 쪽도 같은 자리에 한 줄. **노력 하(下), 검사 가능, 효과 큼.**

### D2. 이진 직렬화 프로젝트에서는 "참조가 남으면 보존"이 통째로 꺼집니다

이 패키지의 **1번 강점**이 소비 프로젝트의 설정 하나에 따라 조용히 무력화됩니다.

근거 — `코드` + `인용`:

- `UnityAssetGateway.FindReferenced` (`Editor/Assets/UnityAssetGateway.cs:176`) 는 `.unity`·`.prefab`·
  `.asset` 를 `File.ReadAllText` 로 읽어 (`:195`) **GUID 문자열이 들어 있는지**를 봅니다 (`:201`).
- Unity의 Asset Serialization Mode 가 `Force Binary` 나 `Mixed` 이면 그 파일들에 GUID가
  **텍스트로 존재하지 않습니다.** 검색은 언제나 "참조 없음"을 돌려줍니다.
- 결과: 표에서 행을 지우면 **씬·프리팹이 쓰고 있는 에셋이 경고 없이 삭제됩니다.**
  README가 "지워 버리면 git으로 파일을 되돌려도 GUID가 달라져 배선이 돌아오지 않습니다"라고
  적어 둔 바로 그 사고가, 안전장치가 켜져 있다고 믿는 상태에서 일어납니다.
- SCPPJ는 `m_SerializationMode: 2`(=ForceText)라 **지금은 드러나지 않습니다** (`측정`).
  그래서 이 프로젝트에서 아무리 써 봐도 발견되지 않습니다.

**고치는 법** — 둘 중 하나, 또는 둘 다:

1. **역인덱스를 `AssetDatabase.GetDependencies` 로 만든다.** 이건 AssetDatabase의 의존성 그래프에서
   나오므로 **직렬화 모드와 무관**하고, 텍스트를 읽지 않으니 D4의 비용도 함께 사라집니다. `인용`
2. **최소한 감지해서 멈춘다.** `EditorSettings.serializationMode != ForceText` 면 정리를 건너뛰고
   "참조 조사를 할 수 없어 삭제하지 않습니다"라고 알립니다. **지우지 않는 쪽으로 틀리는 것**이
   이 패키지의 일관된 태도입니다.

> `판단`: 1이 옳은 답이고 2는 그때까지의 방어입니다. 2는 몇 줄이라 지금 넣을 수 있습니다.

### D3. 식별자를 씻지 않고 파일 경로에 붙입니다

`id` 가 그대로 경로가 됩니다 (`CsvRowImporter.cs:51`, `CsvSchemaImporter.cs:71`). `코드`

| 표에 든 값 | 일어나는 일 |
|---|---|
| `Item/Sword` | 없는 하위 폴더를 가리켜 에셋 생성이 실패합니다 |
| `Q:01` · `A*` · `B?` · `<C>` | 윈도우 파일명 금지 문자. 생성 실패 |
| `" Q_01 "` (앞뒤 공백) | 공백이 든 파일명. 다음 임포트에서 `Q_01` 과 다른 것으로 취급 |
| `..` | 산출물 폴더 밖을 가리킵니다 |

어느 쪽이든 리포트에 **오류로 남지 않습니다.** `건너뜀`도 아닙니다 — 식별자가 비어 있지 않으므로
정상 경로를 타다가 Unity 쪽에서 조용히 실패합니다.

**고치는 법**: `Path.GetInvalidFileNameChars()` 로 검사해 **씻지 말고 거부**하십시오. 자동으로 바꿔 주면
표의 `Item/Sword` 와 에셋의 `Item_Sword` 가 갈려 다음에 더 헷갈립니다. 줄 번호를 달아 경고하고
그 행만 건너뛰는 것이 이 패키지의 다른 자리와 일관됩니다.

### D4. 참조 조사 비용 — 미뤄 두었던 실측

`architecture-review §3-3 ①`이 "고치기 전에 재는 것이 순서"라며 미뤄 둔 항목입니다. 쟀습니다.

| 측정 (SCPPJ 기준) | 값 |
|---|---|
| 훑는 파일 수 | **518개** (`.unity`·`.prefab`·`.asset` + ProjectSettings) |
| 훑는 총량 | **119.1 MB** |
| 최대 단일 파일 | 36.6 MB |
| **읽기만 (따뜻한 캐시)** | **0.39초** |

이 값이 **행이 사라진 표 하나마다 한 번씩** 듭니다. 읽기 위에 후보 GUID 수만큼의 `string.Contains`
가 더 붙습니다(후보가 20개면 실질 훑는 양이 20배).

창의 `다시 훑기` 는 표마다 `Plan()` → `PlanReconcile` 을 부르므로,
**사라지는 행이 있는 표 수만큼 반복**합니다. 거기에 표마다 `FindCsvPath`(프로젝트 전역
`AssetDatabase.FindAssets`)가 한 번씩 더 붙습니다 (`CsvPipelineWindow.Tables.cs:93`).

`판단`: SCPPJ 규모(119MB)에서는 아직 견딜 만합니다. 다만 **차가운 캐시**이거나 에셋이 수 GB인
상용 규모에서는 자릿수가 달라집니다. D2를 `GetDependencies` 역인덱스로 고치면 **이 항목이 함께
없어집니다** — 두 문제의 답이 같습니다. 그래서 D2의 우선순위가 D4보다 위입니다.

### D5. 간판 기능이 자기 프로젝트에서 한 번도 쓰이지 않았습니다

`측정` — SCPPJ의 `[CsvAsset]` 사용은 **0건**입니다. 임포터 9개가 전부 코드 상속입니다.

```
Assets/_Project/02.Scripts/Editor/CsvImporters/  →  9개 파일, 전부 CsvRow/Group/Patch/Singleton 상속
[CsvAsset] 을 쓴 타입                             →  0개
```

`[CsvAsset]` 은 v0.2.0에서 **진입 장벽을 없애기 위해 넣은 핵심**이고, README의 첫 코드 블록이며,
스토어에 낸다면 첫 화면이 될 기능입니다. 그런데 **실사용으로 검증된 적이 없습니다.**

이게 왜 위험한지는 이미 한 번 드러났습니다 — 이 경로는 `자동 연결이 아무 필드도 쓰지 못하는` 채로
나갔다가 나중에 고쳐졌습니다 (`79ad266`). 그동안 검사는 통과하고 있었습니다.

`판단`: SCPPJ의 임포터 9개 중 속성만으로 표현되는 것을 전환하는 것은 기능 추가가 아니라
**검증**입니다. 남는 것(다형 생성·중첩 구조체·그룹핑)이 무엇인지도 그때 정확히 드러납니다 —
지금은 "대략 5개"라는 추정만 있습니다.

### D6. CI가 없습니다

`측정` — `.github` 디렉터리 자체가 없습니다. 검사 **118건**이 있는데 **자동으로 도는 곳이 없습니다.**
사람이 유니티를 열어 Test Runner를 돌려야만 압니다.

이 패키지의 검사 대부분은 이제 `MemoryAssetGateway` 덕에 프로젝트 없이 도는 단위 검사입니다
(v0.8.0의 1순위 시행 결과). **즉 CI에 올리기 가장 좋은 상태인데 안 올려 두었습니다.**

GameCI의 `unity-test-runner` 는 개인 라이선스로도 무료로 EditMode 검사를 돌립니다. `인용`
라이선스 활성화가 한 번의 수동 단계로 필요합니다.

여기에 `architecture-review §3-1`의 **드리프트 검사**를 얹으면 한 벌이 됩니다 — `Plan()` 이 이미
"표와 에셋이 어긋나는가"를 계산하므로, 정적 진입점 하나와 `-executeMethod` 로 **표를 고치고 굽기를
잊은 커밋을 CI가 종료코드로 잡습니다.**

## 4. 경쟁 지형 — 한 축을 놓치고 있었습니다

지난 조사는 **에셋스토어의 CSV→SO 도구들**만 봤습니다. 실제로 이 문제를 푸는 개발자가 가장 많이
쓰는 것은 스토어가 아니라 **OSS**입니다. 그중 확실한 강자가 하나 있습니다.

### BakingSheet (cathei) — ★454, 모바일 상용 출시 실적 있음 `인용`

정면 경쟁이 아니라 **다른 축**입니다. 그래서 비교가 유용합니다.

| | **이 패키지** | **BakingSheet** |
|---|---|---|
| 성격 | 에디터 전용 **에셋 생성기** | 스키마 우선 **ORM + 런타임 배포** |
| 산출물 | ScriptableObject 에셋 | C# 객체 + JSON (SO 변환기는 부속) |
| 원본 | CSV · TSV · 구글 시트 | **Excel** · 구글 시트 · CSV · JSON |
| 스키마 정의 | 속성 `[CsvAsset]` 또는 상속 | `Sheet<TRow>` 상속 (**코드 필수**) |
| **표 간 참조** | 이름으로 찾는 `ObjectReference` (동명이인에 취약) | **`Sheet<>.Reference` 로 타입 안전 + 무결성 검사** |
| 중첩 타입 | **없음** (`SerializedPropertyType.Generic` 미처리) | 있음 (구조체·클래스) |
| Dictionary 열 | **없음** | 있음 |
| 세로 리스트 / 2차원 | **없음** | `VerticalList<T>` · `SheetRowArray<TElem>` |
| 검증 훅 | **없음** (`AfterRebuildAll` 하나뿐) | `PostLoad` · 사용자 정의 검증기 |
| 런타임 배포 | 해당 없음 (에셋이 곧 배포물) | JSON 직렬화 |
| **에디터 창** | **있음** (표·시트·설정) | 없음 |
| **적용 전 미리보기 / 필드 diff** | **있음** | 없음 |
| **참조 남은 에셋 보존** | **있음** (단 D2 참고) | 없음 |
| **역방향 내보내기 (에셋 → 표)** | **있음** | 없음 |

`판단`: **차별화 축이 선명해졌습니다.** BakingSheet가 이기는 곳은 *스키마 표현력*(중첩·사전·표 간
참조·검증)이고, 이 패키지가 이기는 곳은 *에디터 안에서의 안전과 가시성*(미리보기·보존·왕복)입니다.

두 목록은 겹치지 않습니다. 그래서 방향이 둘로 갈립니다.

- **깊게** — 안전과 가시성을 더 밀어붙인다. §2의 D1~D3이 정확히 그 자리이고, 지금 **약속이 깨져 있는**
  곳입니다. 다른 도구가 애초에 하지 않는 일이라 따라오기도 어렵습니다.
- **넓게** — 스키마 표현력을 좇는다. 중첩 타입·표 간 참조 검사·Dictionary. 노력이 크고,
  이미 성숙한 도구가 있는 자리로 걸어 들어가는 것입니다.

**깊게가 맞다고 봅니다.** 넓게 가면 BakingSheet의 열등한 사본이 되고, 그쪽은 무료입니다.

### 스토어 직접 경쟁군

지난 조사 이후 12일이라 변화 없습니다. 재조회했고 그때의 판단은 그대로입니다 —
직접 경쟁군은 여전히 평점이 붙지 않았고, 실질 강자(Scriptable Sheets)는 CSV 변환기가 아니라
**에디터 안 격자 뷰**입니다.

## 5. 배포 — 지금 가장 값싼 개선

`측정` — 저장소가 **private** 입니다. 이것 하나가 셋을 동시에 막고 있습니다.

1. **설치가 어렵습니다.** README가 **한 절 전체**를 "비공개 저장소라면 자격증명이 미리 있어야 합니다"에
   쓰고 있습니다. Package Manager는 대화형 인증을 못 합니다. 기능 문제가 아니라 유통 문제입니다.
2. **OpenUPM에 올릴 수 없습니다.** OpenUPM은 GitHub의 공개 OSS 저장소만 받습니다. 태그를 감지해
   자동으로 배포하고, 등록 자체가 발견 경로가 됩니다. `인용`
3. **평판이 쌓이지 않습니다.** 라이선스는 이미 MIT입니다. 비공개 MIT는 아무에게도 닿지 않습니다.

`판단`: 지난 조사 §8-2의 "무료 공개 vs 유료"는 §4의 지형을 보고 나면 답이 더 분명해집니다.
이 니치의 수요 신호는 약하고, 실제 사용자는 OSS를 씁니다. **공개 + OpenUPM**이 평점 0인 유료 에셋보다
얻을 것이 많습니다. 그리고 그 길은 **영문화 61파일을 먼저 끝내지 않아도 열립니다** — OpenUPM은
언어를 요구하지 않습니다.

> OpenUPM의 조건 하나: 등록 후 **3개월 안에 릴리스가 하나는 있어야** 유지됩니다. `인용`

## 6. 우선순위

노력 대비 효과 순입니다. 위 셋은 전부 **작고, 검사로 못 박을 수 있고, 상품의 주장을 지키는 것**입니다.

### 1순위 — 약속이 깨진 자리를 막는다

| 항목 | 노력 | 왜 먼저인가 |
|---|---|---|
| **D1 중복 식별자 경고** | 하 | 데이터 손실이 조용히 일어나는 유일하게 남은 자리. `BakeEach`의 `HashSet.Add` 반환값 한 줄 |
| **D2-2 직렬화 모드 감지** | 하 | 안전장치가 꺼져 있는 줄 모르는 상태를 없앱니다. 지우지 않는 쪽으로 틀립니다 |
| **D3 식별자 위생 검사** | 하 | 씻지 말고 거부. 줄 번호를 달아 그 행만 건너뜁니다 |

### 2순위 — 자동으로 지켜지게 한다

| 항목 | 노력 | 얻는 것 |
|---|---|---|
| **D6 CI (GameCI + EditMode)** | 중 | 검사 118건이 사람 없이 돕니다. 지금이 올리기 가장 좋은 상태입니다 |
| **드리프트 검사** (`arch §3-1`) | 하 | `Plan()`이 이미 계산합니다. 진입점 하나 + `-executeMethod` |
| **D5 SCPPJ를 `[CsvAsset]`으로 전환** | 중 | 간판 기능의 첫 실사용. 속성으로 안 되는 표가 무엇인지 **추정이 아니라 측정**이 됩니다 |

### 3순위 — 비용을 없앤다 (D2-1과 한 몸)

| 항목 | 노력 | 얻는 것 |
|---|---|---|
| **참조 역인덱스 (`GetDependencies`)** | 중 | D2의 정답이면서 D4의 119MB 훑기가 함께 사라집니다 |
| `DiscoverAll()` 캐시 · 창의 `FindCsvPath` 캐시 | 하 | 훑기가 표 수에 비례해 무거워지는 것을 끊습니다 |

### 4순위 — 낼 것으로 정해진 뒤

영문 문서 61파일 (B2) · AI 고지 (N1) · 네트워크·키 보관 고지 (R3·N4) · 공개 전환 + OpenUPM (§5).

### 순위에 넣지 않은 것과 그 이유

- **중첩 타입 · Dictionary · 표 간 참조 검사** — §4의 "넓게" 쪽입니다. 노력이 크고, 그 자리에는
  이미 무료로 더 잘하는 도구가 있습니다. 깊게 가는 편이 낫다고 봅니다.
- **Excel(.xlsx) 직접 읽기** — 외부 의존성이 붙습니다. 지금 의존성 0이라는 점은 스토어 심사와
  설치 양쪽에서 자산입니다. 구글 시트 경로가 실질적으로 같은 필요를 덮습니다.
- **UI Toolkit 이전** — `ui-review §5`의 판단이 그대로입니다. 화면이 그만큼 복잡해지면 그때가 순서입니다.
- **`CsvReader.Read` 제거** — SCPPJ가 아직 씁니다. **D5 전환이 끝난 뒤**가 순서인 것도 그대로입니다.

## 7. 시행 결과 — 1순위 (2026-08-21, v0.10.0)

§6의 1순위 셋을 순서대로 시행했습니다.

| 항목 | 시행 전 (v0.9.1) | 시행 후 (v0.10.0) |
|---|---|---|
| Editor 코드 | 46파일 / 7,639줄 | **48파일 / 8,059줄** |
| 검사 | 15파일 / 2,148줄 · 118건 | **18파일 / 2,628줄 · 154건** |
| 배치 실행 결과 | — | **통과 152 / 실패 0 / 건너뜀 2** (화면이 필요한 그리기 검사 2건) |
| 컴파일러 경고 | 0 | **0** |

검사는 Unity 2022.3.62f3(선언한 최소 버전) 배치 모드에서 돌렸습니다.

### D1 — 겹친 식별자

`CsvIdClaims` 라는 순수 타입 하나로 갈랐습니다. 굽기(`BakeEach`)와 미리보기(`ClaimForPlan`)가
**같은 판정을 씁니다** — 다르면 미리보기가 있으나 마나가 되기 때문입니다.

자리는 **식별자가 아니라 경로**로 가립니다. 같은 식별자라도 파생 타입에 따라 다른 폴더에 놓이면
서로 다른 에셋이고, 그때 경고하면 없는 문제를 있다고 말하게 됩니다.

**예상하지 못했던 소득**: 대소문자를 다루다 보니 지금까지 이름이 없던 문제가 드러났습니다 —
`Sword` 와 `sword` 는 윈도우에서 같은 파일, macOS·리눅스에서는 다른 파일입니다. 즉 **표는 그대로인데
어느 PC에서 구웠느냐에 따라 에셋 개수가 달라집니다.** 겹침으로 함께 잡습니다.

`CsvPatchImporter` 도 이제 이름·경로를 넘깁니다. 정리를 하지 않아 대조에는 쓰이지 않지만,
같은 에셋을 두 행이 덮어쓰는 것을 골격이 알아채게 하려는 것입니다.

### D2 — 이진 직렬화

게이트웨이가 **"모른다"고 말할 수 있게** 했습니다 (`ICsvAssetGateway.ReferenceScanBlocked`).
경계가 이미 있었기에 값 하나를 늘리는 것으로 끝났고, `MemoryAssetGateway` 가 그 상황을 흉내 내
**Unity 프로젝트의 설정을 바꾸지 않고** 검사할 수 있습니다.

보존의 뜻이 둘로 갈렸습니다. "참조가 남아 보존"은 정상 동작이고, "조사할 수 없어 보존"은 문제입니다.
계획에 같은 말로 적으면 안전장치가 꺼진 사실이 "잘 지켜지고 있다"로 읽히므로, 후자만 계획에
경고로 올려 표를 목록 위로 보냅니다.

### D3 — 식별자 위생

금지 문자 목록을 `Path.GetInvalidFileNameChars()` 로 가져오지 **않았습니다.** 그 목록은 돌아가는
운영체제마다 달라서, 그대로 쓰면 **윈도우에서 거절된 표가 macOS에서는 통과합니다.** 고정 목록을 둡니다.

씻어 주지 않고 거절합니다. `Item/Sword` 를 `Item_Sword` 로 바꿔 구우면 표에 적힌 이름과 에셋 이름이
갈라져, 다음에 그 표를 읽는 사람이 더 헷갈립니다.

### 남은 것

§6의 2순위(CI·드리프트 검사·`[CsvAsset]` 자기 적용)와 3순위(참조 역인덱스)는 그대로입니다.
D2를 `GetDependencies` 역인덱스로 고치는 일은 아직 남아 있고, 이번 시행은 **그때까지의 방어**입니다.

## 8. 판단 보류 — 사람이 정해야 할 것

1. **깊게냐 넓게냐.** §4의 두 방향은 양립하지만 순서를 정해야 합니다. 이 문서는 깊게를 권합니다.
2. **공개로 돌릴 것인가.** §5의 셋이 여기 달려 있고, 영문화보다 훨씬 쌉니다. 다만 되돌리기 어렵습니다.
3. **AI 고지의 범위.** N1은 스토어에 낼 때의 의무입니다. GitHub 공개만 한다면 의무는 아니지만,
   적어 두는 편이 이 저장소의 다른 문서들과 태도가 맞습니다.
4. **D2를 어디까지.** 감지해서 멈추는 것(하)까지만 할지, 역인덱스(중)까지 갈지.
   전자는 지금 넣을 수 있고 후자는 D4까지 함께 끝냅니다.
