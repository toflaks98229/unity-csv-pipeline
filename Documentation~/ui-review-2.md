# UI/UX 2차 조사와 개선 — 기준을 밖에서 가져오다

조사·적용일 2026-08-21 · 대상 `CsvPipelineWindow` (v0.10.0 → v0.11.0)

> [ui-review](ui-review.md)(1차, v0.8.0 → v0.9.0)가 남긴 자리에서 이어집니다.
> 1차는 **VS Code · Blender · Rider** 를 참고해 "훑을 수 있는 목록"을 만들었습니다.
> 이번에는 **Unity 자신이 내놓은 기준**을 찾아 그것과 대조했습니다. 결과가 달랐습니다 —
> 인상으로는 잘 만든 화면이었는데, 기준을 대자 **두 가지를 대놓고 어기고 있었습니다.**

## 1. 이번에 새로 찾은 출처

1차 조사가 놓친 것이 하나 있었습니다. **Unity 에 공식 UX 기준 문서가 있습니다.**

| 출처 | 종류 | 여기서 가져온 것 |
|---|---|---|
| **[Unity Editor Design System](https://unityeditordesignsystem.unity.com/foundations/ux-checklist)** | **1차 · 유니티 공식 UX 표준** | 번호가 붙은 규칙(US-####). 지켰는지 아닌지를 **판정할 수 있습니다** |
| **[같은 곳 · 접근성](https://unityeditordesignsystem.unity.com/fundamentals/accessibility)** | 1차 | 명암비 **4.5:1 / 3:1**, 색만으로 뜻을 나르지 않기, 키보드 전용 접근 |
| **Unity Addressables** (로컬 설치본 소스) | 1차 · 유니티 자체 도구 | 목록 검색에 `UnityEditor.IMGUI.Controls.SearchField` 를 씀 — 지우기(×) 단추와 `SetFocus()` 가 딸려 옵니다 |

`인상` 이 아니라 `판정` 이 가능해졌다는 것이 이번 조사의 가장 큰 소득입니다.

## 2. 기준에 대조한 결과

`측정` = 코드에서 확인하거나 실제로 재 본 것입니다.

| 표준 | 요구 | 고치기 전 |
|---|---|---|
| **US-0180** | 모든 화면이 **마우스 없이 키보드만으로** 닿을 수 있어야 함 | ❌ **대놓고 위반.** 목록에 키로 닿을 방법이 **하나도** 없었습니다 |
| **US-0173** | 글자 **4.5:1**, 아이콘·비활성 **3:1** | ❌ **위반.** 재 보니 어두운 스킨 **2.6:1** |
| **US-0240** | 모든 단추·아이콘·비활성 요소에 툴팁. 비활성은 **왜 꺼졌는지**까지 | ⚠️ 상태 아이콘에만 있었습니다. 도구 줄 단추·검색·`찾기`·`지금 굽기` 는 없음 |
| **US-0171** | 색을 뜻의 유일한 표시로 쓰지 않기 | ✅ 1차에서 이미 해결 (아이콘 + 낱말 + 색) |
| **US-0205** | 빈 화면을 그냥 비워 두지 않기 | ✅ 1차에서 이미 해결 |
| **US-0202** | 오류 안내는 문제·원인·해법을 담아 실행 가능하게 | ✅ 대체로 |
| **US-0212 · 0213** | 단추 이름은 동사, 세 낱말 이내, 문장부호로 끝내지 않기 | ✅ |
| 반응형 | 최소 너비에서 **가로 스크롤이 생기지 않아야** 함 | ❌ **위반.** 칸 너비가 고정 픽셀이라 좁히면 잘렸습니다 |
| 창 제목 | 그 창을 여는 메뉴 항목의 이름과 같아야 함 | ❌ 메뉴 `CSV 파이프라인 창` / 제목 `CSV Pipeline` |

### 2-1. 색이 왜 2.6:1 이었나 — 원인이 방식에 있었습니다

1차 조사가 만든 `ColoredLabel` 은 `GUI.contentColor` 에 **반투명한 색**(흰색 알파 0.45)을 넣었습니다.
`Color(1,1,1,0.45)` 라고 적어 두면 "흰색을 45% 로 흐리게" 로 읽힙니다. 그런데 `contentColor` 는
**바탕 스타일의 글자색과 곱해집니다.**

```
어두운 스킨 라벨의 글자색  #C4C4C4
× contentColor            (1, 1, 1, 0.45)
= 실제로 찍히는 색         #C4C4C4 를 알파 0.45 로 #383838 위에 → #777777
```

`#777777` 대 `#383838` 의 명암비는 **2.62:1** 입니다. 요구치의 절반이 조금 넘습니다.
**적어 둔 값과 화면에 나오는 값이 다르니, 아무도 재 볼 수 없었습니다.**

## 3. 고친 것

### 3-1. 색을 잴 수 있게 만들었습니다

`GUI.contentColor` 를 버리고 **글자색이 정해진 스타일**을 씁니다. 이제 적어 둔 값이 곧 찍히는 값입니다.

색과 명암비 계산을 `CsvPalette` 한 곳에 모으고, **검사가 두 스킨 모두에서 기준을 지킵니다.**

> 이 검사는 만들자마자 값을 했습니다. 손으로 고른 첫 값에서 **5건이 떨어졌습니다** —
> 어두운 스킨의 Muted(4.32:1)와 밝은 스킨의 Warning(4.41:1)이 기준에 못 미쳤고, 밝은 스킨의
> 주의와 오류가 서로 너무 비슷했습니다. 눈으로는 넷 다 멀쩡해 보였습니다.
> 나머지 2건은 **제가 기준을 잘못 적용한 것**이었습니다(§3-1 아래 참고). 지금 값은 계산이 통과시킨 값입니다.

| 색 | 어두운 스킨 | 밝은 스킨 | 쓰임 |
|---|---|---|---|
| Muted | 4.72:1 | 4.73:1 | 덜 중요한 글자 |
| Accent (파랑) | 5.17:1 | 4.71:1 | 바뀌는 것 |
| Warning (노랑) | 7.26:1 | 4.89:1 | 조심할 것 |
| Danger (빨강) | 4.77:1 | 4.84:1 | 잘못된 것 |

*(한 줄 걸러 깔리는 바탕까지 재서 **불리한 쪽**을 적었습니다.)*

**뜻 색을 하나 늘렸습니다.** 되돌릴 수 없는 삭제와 고쳐야 할 오류가 같은 빨강이었는데,
Unity 의 규약대로 **노랑(주의)** 과 **빨강(오류)** 을 갈랐습니다. 보존·건너뜀도 노랑입니다 —
둘 다 "표에 적힌 대로 되지 않았다"는 뜻이라 눈에 걸려야 합니다.

색끼리 서로 구분되는지도 검사가 봅니다. 셋이 비슷해지면 나눈 뜻이 없습니다.

**줄을 가르는 선에는 3:1 을 요구하지 않습니다.** 처음에는 요구했다가 걷었습니다 — 그 선은
장식입니다. 줄이 갈린다는 사실은 한 줄 걸러 깔리는 바탕이 이미 나르고, 하이라이트 규칙(WCAG 1.4.11)도
장식은 뺍니다. 3:1 을 맞추려면 굵은 검은 줄이 되어 오히려 화면이 시끄러워집니다.
대신 **아예 보이지 않게 되지는 않았는지**만 검사가 봅니다.

### 3-2. 키보드로 다 됩니다 (US-0180)

| 키 | 하는 일 |
|---|---|
| `↑` `↓` · `Home` `End` | 표 고르기 |
| `→` `←` | 펼치기 · 접기 |
| `Space` | 펼침 뒤집기 |
| `Enter` | 고른 표 굽기 |
| `Ctrl`(`⌘`)`+F` | 찾기 |
| `Esc` | 검색어 지우기 |

세 가지 판단을 코드에서 떼어 내 **검사가 지키게** 했습니다.

1. **어느 키가 무슨 뜻인가** (`CsvListKeys.Read`) — `Alt`·`Shift` 가 붙은 조합은 목록 명령이
   아닙니다. 가로채면 사람이 기대한 다른 동작이 사라집니다.
2. **끝에서 감싸지 않는다** (`CsvListKeys.Move`) — 감싸면 목록의 끝을 느끼지 못합니다.
3. **글자를 치고 있을 때는 넘기지 않는다** — 검색 칸에 초점이 있으면 `↑` `↓` 는 그쪽 것입니다.
   대신 검색 칸에서 `↑` `↓` 를 누르면 **목록으로 넘어갑니다.** (Unity 자신의 `SearchField` 가 주는 신호)

고른 표는 **번호가 아니라 파일 이름으로** 들고 있습니다. 거르기나 훑기로 목록이 바뀌어도
골라 둔 것이 엉뚱한 표로 옮겨 가지 않게 하려는 것입니다. 화면 밖에 있으면 `GUI.ScrollTo` 로 끌어옵니다.

### 3-3. 그 밖에

| 무엇 | 고친 뒤 |
|---|---|
| **툴팁** (US-0240) | 모든 단추·검색·상태에 붙였고, **비활성 단추에는 왜 꺼졌는지**를 적었습니다 |
| **좁은 창** | 필드 변경 칸이 창 너비를 따릅니다. 줄여 보인 값은 **툴팁에 전체가** 담깁니다 |
| **검색 칸** | 유니티 자신의 `SearchField` — 지우기(×) 단추가 생겼습니다 |
| **보기** | `바뀌는 것만` 하나였던 것이 셋으로 (`손볼 것만` 추가) |
| **오른쪽 누르기** | 그 표의 차림표. 할 수 없는 항목은 **감추지 않고 흐리게** 둡니다 |
| **상태 막대** | 줄 맨 왼쪽에 상태 색 막대. 자리까지 더해 세로로 훑기가 쉬워집니다 |
| **마우스 올림** | 줄이 밝아집니다. 1차에서 미룬 것을 다시 봤습니다 (아래) |
| **마지막 훑은 시각** | 상태 줄에 붙습니다. 낡은 화면을 믿지 않도록 |
| **연동 갈래 검색** | 설정이 스무 개를 넘으면 눈으로 못 찾습니다 |
| **창 이름** | 메뉴와 제목을 `CSV 파이프라인` 으로 맞췄습니다 |

## 4. 1차에서 미뤘던 것을 다시 본 결과

### 마우스 올림 — 넣었습니다

1차는 "`Repaint` 를 마우스 움직임마다 불러야 해서 비싸다"며 미뤘습니다. 맞는 판단이었지만
**값을 줄일 방법이 있었습니다.**

- 마우스 움직임을 **창이 앞에 있을 때만** 받습니다. (`OnFocus`/`OnLostFocus`)
- 올라간 줄이 **바뀔 때만** 다시 그립니다. 같은 줄 위에서 움직이는 동안에는 아무 일도 없습니다.

**표 갈래에만 넣었습니다.** 연동 갈래는 줄 자체가 단추가 아니라, 밝아지면 **누를 수 있다고
잘못 말하게 됩니다.** 일관성보다 정확함이 먼저입니다.

### UI Toolkit 이전 — 여전히 아닙니다

1차의 판단이 그대로입니다. 이번에 더해진 근거가 하나 있습니다 — **IMGUI 로도 US-0180 을
지킬 수 있었습니다.** 옮겨야 할 이유가 "키보드가 안 돼서" 였다면 이제 그 이유가 없습니다.

### 트리 보기 · 좌우 비교 뷰어 — 여전히 아닙니다

표는 여전히 한 폴더에 평평하고, 필드 값은 여전히 대부분 한 줄입니다.
값이 길 때는 **툴팁에 전체가 담기게** 한 것으로 갈음했습니다.

## 5. 확인한 방법 — 이번에 달라진 것

1차 조사는 이렇게 적었습니다.

> 배치 실행에서는 그리기 검사 2건이 **건너뜀**으로 남습니다.

**그 전제가 틀렸습니다.** `-nographics` 를 빼고 띄우면 배치 실행에서도 창을 열고 그릴 수 있습니다.
이번에 실제로 해 보고 알았습니다.

그래서 그리기 검사를 고쳤습니다. 이제 **창을 여는 데 실패했을 때만** 건너뜁니다. 열린 뒤에 난
예외는 감싸지 않습니다 — 그건 진짜 결함이기 때문입니다.

덮는 범위도 늘렸습니다. 갈래 셋 × 보기 셋 · 빈 화면 안내 · **최소 너비(560px)** 까지 그려 봅니다.
마지막 것이 중요합니다 — 고정 픽셀 폭이 잘리는지는 **좁혀 봐야만** 드러납니다.

## 6. 하지 않은 것과 그 이유

- **다중 선택** — 고른 표 여럿을 한 번에 굽는 것. 지금은 `전체 다시 굽기` 가 그 자리를 덮고 있고,
  중간 규모(서넛)를 위해 선택 모델을 늘리면 키 규칙이 두 배로 복잡해집니다.
- **정렬 바꾸기** — 지금은 "무거운 상태부터" 하나뿐입니다. 이름순으로 보고 싶을 때가 있겠지만,
  **손볼 것이 위로 오는 것**이 이 창의 목적이라 기본을 흔들 이유를 아직 찾지 못했습니다.
- **설정 갈래의 키보드 이동** — 그쪽은 인스펙터 꼴이라 `Tab` 이 이미 유니티 규칙대로 돕니다.
- **스킨 배경색을 실제 값에서 읽기** — Unity 가 API 로 알려 주지 않습니다. 기본 스킨 값을 적어
  두고 그렇다고 밝혀 두었습니다. 스킨을 손댄 프로젝트에서는 실제와 다를 수 있습니다.
