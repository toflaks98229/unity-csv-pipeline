# UI/UX 조사와 개선 — CSV Pipeline 창

조사·적용일 2026-08-10 · 대상 `CsvPipelineWindow` (v0.8.0 → v0.9.0)

> 이 창은 **에셋을 지울 수 있는 도구**입니다. 그래서 "예뻐 보이는가"보다
> **지금 무엇이 일어날 참인지 한눈에 읽히는가**를 앞에 두었습니다.
> 아래 판단은 전부 근거를 밝히고, 근거가 인상뿐인 것은 그렇다고 적었습니다.

---

## 1. 무엇을 보고 왔나

유니티 밖까지 봤습니다. 다만 **1차 자료를 우선**했습니다 — 이 프로젝트에 실제로 깔려 있는
유니티 자신의 패키지 소스가, 블로그 글보다 훨씬 확실한 근거입니다.

| 출처 | 종류 | 여기서 가져온 것 |
|---|---|---|
| **Unity App UI** (`com.unity.dt.app-ui`, 로컬 설치본) | 1차 · 유니티 자체 디자인 시스템 | 간격 계단이 **4px 배수**(4·8·12·16·24·32)로 못 박혀 있음 |
| **Unity Addressables** (로컬 설치본 소스) | 1차 · 유니티 자체 도구 | 접힘 상태를 **`SessionState`** 에 실어 도메인 재적재를 넘김 · 넘침 메뉴에 `_Popup` 아이콘 · 경고에 `console.warnicon.sml` |
| **Blender 인터페이스 지침** | 2차 | 관련 속성은 **제목으로 묶고**, 덜 쓰는 것은 **접어 둔다** · 속성마다 상태를 알리는 작은 표시(decorator) · 프리셋을 머리줄로 올려 자리를 아낌 |
| **VS Code 소스 제어 패널** | 2차 | 변경 종류를 **줄 맨 앞 한 칸**(M/U/D)에 고정 · 개수를 배지로 · 목록/트리 전환 |
| **JetBrains Rider 비교 뷰어** | 2차 | 이전/이후를 **좌우 같은 높이**로 세워 눈이 가로로만 움직이게 함 |
| **빈 화면(empty state) 설계 통념** (Linear·Notion 사례 정리 글) | 2차 | **제목 → 왜 → 다음 행동 하나**. 필터가 원인일 때는 **어느 필터가 범인인지** 짚어 줌 |

### 밖에서 본 것 중 이 창에 실제로 옮긴 규칙

1. **상태는 늘 줄 맨 앞 같은 자리에.** (VS Code) 눈이 세로 한 줄만 훑으면 목록 전체가 읽힙니다.
2. **색만으로 뜻을 나르지 않는다.** 아이콘(모양) + 낱말 + 색 셋을 같이 씁니다.
3. **간격은 눈대중이 아니라 계단으로.** (Unity App UI) 4·8·12·16 네 단만 씁니다.
4. **도구 줄은 성격으로 묶고 선으로 가른다.** 붙어 있으면 하나로 읽힙니다.
5. **되돌릴 수 없는 것은 자주 쓰는 단추 옆에 두지 않는다.** 넘침 메뉴로 내리고 한 번 더 묻습니다.
6. **빈 화면은 막다른 길이 아니다.** 제목 → 왜 → 다음 행동 하나.
7. **상태는 도메인 재적재를 넘긴다.** (Addressables) 스크립트 한 번 고칠 때마다 초기화되면 안 됩니다.

## 2. 고치기 전 창에서 찾은 것

인상이 아니라 코드에서 확인한 것만 적습니다.

### 2-1. 되돌아오지 않는 상태 — 가장 크게 걸리던 것

갈래·검색어·필터·펼친 표가 **전부 보통 필드**였습니다. 유니티는 스크립트를 고칠 때마다
도메인을 다시 싣고, 그때 이 값들이 통째로 초기값이 됩니다.

> 표 40장 중 하나를 찾아 펼쳐 놓고 → 코드 한 줄 고치고 → 돌아오면 처음부터.

여기에 `OnEnable`이 `_scanned = false`를 걸어 두어, 돌아온 자리에서 **전체 재훑기까지** 다시
돕니다. 자리를 잃고 기다리기까지 합니다.

### 2-2. 두 갈래가 스크롤 위치를 함께 씀 — 결함

`_scroll` 필드 하나를 '표'와 '시트 연동'이 같이 썼습니다. 표를 아래까지 내린 뒤 시트 갈래로
가면, 항목이 셋뿐인데도 화면이 엉뚱한 자리에서 시작합니다.

### 2-3. 시트 목록을 매 프레임 다시 찾음 — 성능

`DrawSheets` 가 `GoogleSheetSync.FindAll()` 을 그릴 때마다 불렀습니다. `FindAll` 은
프로젝트 전체 검색 한 번 + 찾은 개수만큼 에셋 로드입니다. SCPPJ 에는 연동 설정이 23개 있으니
**마우스를 움직이는 동안에도 계속 23번씩** 읽었습니다.

*(실제 밀리초는 재지 않았습니다. 구조상 그렇게 돈다는 것까지가 확인된 사실입니다.)*

### 2-4. 훑을 수 없는 목록

- 표마다 `helpBox` 상자를 둘러 **전부 같은 무게**로 보였습니다. 문제 있는 표와 멀쩡한 표가
  같은 굵기의 테두리를 씁니다.
- 상태를 나르는 것은 오른쪽 끝 요약 글자의 **색뿐**이었습니다. 색맹이면 구분되지 않고,
  밝은 스킨에서는 대비도 낮습니다.
- 정렬이 **파일 이름순 하나**뿐이라, 오류 난 표가 알파벳 순서에 따라 스크롤 아래에 묻혔습니다.
- 변경 줄이 `60 / 180 / 48` 같은 **고정 픽셀**로 잡혀 있고, 표기에 전각 글자
  (`＋ · － ◦ ／`)를 써서 자리마다 폭이 달랐습니다.
- 필드 변경은 `LabelField(label, value)` 라 인스펙터의 1/3 라벨 폭을 따르는데, 그 위 변경 줄은
  고정 폭이라 **두 층의 세로선이 서로 어긋났습니다.**

### 2-5. 위험한 것과 안전한 것이 같은 무게

`전체 다시 굽기`(사라진 산출물 삭제)와 `에셋을 표로 내보내기`(원본 표 덮어쓰기)가
`다시 훑기` 와 **같은 모양의 단추로 나란히** 있었고, 확인도 묻지 않았습니다.
내보내기는 시트 연동을 켠 표에서 시트와 어긋나게 만들 수 있습니다.

### 2-6. 자리를 차지하는 고정 문구

`"이 창은 누르기 전까지 아무것도 쓰지 않습니다"` 가 갈래 줄 오른쪽에 **늘** 붙어 있었습니다.
값진 약속이지만 **한 번 읽으면 되는 말**이 매번 갈래 이름과 자리를 다툽니다.

### 2-7. 빈 화면이 막다른 길

- `"바뀌는 표가 없습니다"` — 필터 때문인지 진짜 없는지 알 수 없고, 할 수 있는 것도 없음.
- 표가 하나도 없을 때는 단추 셋이 **모두 같은 무게**로 놓여, 무엇부터 눌러야 할지 알 수 없음.

### 2-8. 아이콘이 하나도 없음

유니티 내장 아이콘이 이 뜻들에 그대로 있는데(`console.erroricon.sml`, `d_Refresh`,
`d_Toolbar Plus/Minus`, `_Popup`, `TestPassed`) 하나도 쓰지 않아, 화면이 전부 글자였습니다.

## 3. 고친 것

### 3-1. 뼈대 — 위·가운데·아래

```
┌────────────────────────────────────────────────────────────┐
│  표 │ 시트 연동 │ 설정                                  [?] │  ← 갈래
├────────────────────────────────────────────────────────────┤
│ [↻ 다시 훑기] │ [바뀌는 것만] [🔍         ]           [⋯] │  ← 도구 줄
├────────────────────────────────────────────────────────────┤
│                                                            │
│   ▸ ⛔ ItemData    Items.csv          생성 2 / 삭제 1      │  ← 목록
│   ▸ ↻  CardData    Cards.csv          갱신 12              │
│   ▸ ✓  ClueData    Clues.csv          바뀌는 것 없음        │
│                                                            │
├────────────────────────────────────────────────────────────┤
│ 표 12 · 바뀜 3 · 문제 1        누르기 전까지 쓰지 않습니다  │  ← 상태 줄
└────────────────────────────────────────────────────────────┘
```

**상태 줄을 새로 뒀습니다.** 갈래마다 흩어져 있던 개수 요약과, 갈래 줄을 차지하던 안전 문구가
둘 다 여기로 내려왔습니다. 늘 같은 자리라 찾을 필요가 없고, 위쪽은 조작에만 쓰입니다.

### 3-2. 목록을 훑을 수 있게

| 고치기 전 | 고친 뒤 |
|---|---|
| 표마다 `helpBox` 테두리 | 테두리 없이 **한 줄 걸러 옅은 바탕** |
| 상태 = 오른쪽 글자색 | **줄 맨 앞 고정 칸**에 아이콘 + 오른쪽에 낱말과 색 |
| 이름순 정렬 | **무거운 상태부터** (막힘 → 문제 → 삭제 → 변경 → 같음), 같으면 이름순 |
| 삼각형만 눌러야 펼쳐짐 | **줄 전체가 펼침 단추** |
| 고정 픽셀 + 전각 글자 | 계단 간격 + 아이콘, `열 / 이전 / → / 이후` 를 **같은 가로 위치**에 세움 |

정렬 규칙은 눈에 보이지 않는 판단이라 코드에서 떼어 냈습니다. `CsvPlanStatus.Of(plan)` 하나가
아이콘·색·정렬·필터를 모두 정하고, **검사 10건이 그 규칙을 지킵니다.**

### 3-3. 위험한 것을 분리

`전체 다시 굽기` 와 `에셋을 표로 내보내기` 를 넘침 메뉴 `[⋯]` 로 내리고, 각각 **무슨 일이
일어나는지 적은 확인 대화**를 붙였습니다.

시트 갈래에서는 `전부 비교만` 을 `전부 받기` **왼쪽**에 뒀습니다. 받기는 로컬 표를 덮어쓰므로
비교가 먼저인 것이 순서인데, 전에는 받기가 왼쪽이라 순서가 거꾸로 읽혔습니다.

### 3-4. 빈 화면을 길로

셋 다 **제목 → 왜 → 다음 행동 하나** 로 바꿨습니다.

- **표가 없을 때** — `Quick Start 샘플 가져오기` 가 큰 단추, 나머지 둘은 작은 단추.
- **걸리는 것이 없을 때** — 검색어 때문인지 필터 때문인지 **짚어 주고**, 원인별 단추를 답니다.
  (필터가 켜져 있을 때만 `필터 끄기` 가 나타납니다)
- **연동 설정이 없을 때** — `설정 만들기` 하나만 큰 단추.

### 3-5. 결함 셋

| 무엇 | 어떻게 |
|---|---|
| 갈래끼리 스크롤 공유 | 갈래마다 따로 (`_tableScroll` · `_sheetScroll` · `_settingsScroll`) |
| 시트 목록 매 프레임 재검색 | 한 번 모아 들고 있다가, `다시 훑기` 와 설정 생성 때만 버림 |
| `OnGUI` 안에서 진행 막대 | 사람이 눌러서 부른 훑기에서만 띄움 (Layout/Repaint 어긋남 방지) |

### 3-6. 치수와 아이콘을 한 벌로

`CsvEditorUI` 에 모았습니다. 간격은 **4 / 8 / 12 / 16** 네 단(Unity App UI 계단), 줄 높이 20,
상태 칸 18. 아이콘은 **없으면 글자로 물러섭니다** — 내장 아이콘 이름은 유니티 판마다 달라질 수
있고, 아이콘 하나 때문에 창이 깨지면 안 되기 때문입니다.

## 4. 확인한 방법

**IMGUI 는 컴파일로 아무것도 보증되지 않습니다.** `Begin/End` 짝이 어긋나도 컴파일은 통과하고
창만 무너집니다. 그리고 그 어긋남은 **화면이 없는 배치 실행에서는 드러나지 않습니다.**

그래서 두 겹으로 확인했습니다.

| 무엇 | 어떻게 | 결과 |
|---|---|---|
| 판정 규칙 | 배치 실행 단위 검사 10건 | 통과 |
| 창 상태가 재적재를 넘는지 | 배치 실행 검사 1건 | 통과 |
| **세 갈래가 실제로 그려지는지** | **화면 있는 에디터**로 창을 열고 강제 리페인트 | **통과** |
| 걸리는 것이 없는 경로 | 같음 | 통과 |

배치 실행에서는 그리기 검사 2건이 **건너뜀**으로 남습니다. 건너뛴 것을 통과로 세지 않도록
검사가 스스로 `Assert.Ignore` 를 냅니다.

```
배치 실행         : 총 112 / 통과 110 / 건너뜀 2
화면 있는 실행    : 총 112 / 통과 112 / 건너뜀 0
```

## 5. 하지 않은 것과 그 이유

- **UI Toolkit 으로 갈아타기** — 유니티 문서도 복잡한 에디터 도구에는 UI Toolkit 을 권합니다.
  다만 이 창은 IMGUI 로 이미 서 있고, 옮기면 **화면은 그대로인데 위험만 새로 생깁니다.**
  UXML/USS 가 필요할 만큼 화면이 복잡해지면 그때가 순서입니다.
- **줄에 마우스를 올렸을 때 밝아지기** — `Repaint` 를 마우스 움직임마다 불러야 합니다.
  창 하나 열어 둔 값으로는 비싼 편이라, 한 줄 걸러 바탕으로 갈음했습니다.
- **표 목록의 트리 보기** — VS Code 의 목록/트리 전환은 파일이 폴더로 갈릴 때 값을 합니다.
  이 창의 표는 한 폴더에 평평하게 놓여 있어 지금은 얻을 것이 없습니다.
- **미리보기의 좌우 비교 뷰어** — Rider 식 두 칸 비교는 값이 길 때 빛납니다. 지금 필드 변경은
  대부분 한 줄짜리라, 같은 가로 위치에 세우는 것으로 충분했습니다. 긴 값이 문제가 되면
  그때 다시 봅니다.
